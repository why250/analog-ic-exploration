# 学习方法

## 1. 发现与筛选

每周搜索结果是候选，不自动等同于高质量项目。检查以下证据：

- 电路类：设计规格、PDK、晶体管级电路、testbench、仿真脚本和结果；布局、DRC/LVS、PEX、EM 或实测是加分项。
- AI 类：LLM/Agent 实际职责、输入输出、EDA 调用、目标函数和验证结果；区分真实运行与概念演示。
- 工具类：安装方式、依赖、API、可运行示例和可验证输出。
- 通用：许可证、版本、文档完整性、复现难度及与个人目标的关联。

不要求所有候选都完整，也不使用机械星级评分。记录关键证据与不确定性，确定一个可执行的下一步。

## 2. 拆解与学习计划

选中项目后创建 `docs/projects/<slug>/index.md`（使用模板）。记录上游版本和证据。厘清规格、架构、电路与仿真入口；定义一项最小实验和验收指标。

## 3. 运行与实验

环境安装及上游源码操作原则上在本地独立 workspace 完成。先运行原始示例，不急于改写或引入 LLM；记录实际环境、命令和日志。然后改变一个可解释的参数、观察结果，并与理论及上游结果比较。可以在实验明确后引入 Agent 自动化，记录其职责、调用和验证。

## 4. 记录与沉淀

每次有实质进展，按需写独立笔记 `docs/projects/<slug>/NN-topic.md`。保留关键图、数据、错误原因和下一步。原始仿真大文件留在本地，仓库只保存合法的小型证据与必要脚本。

完成后记录学到了什么、哪些方法可复用、哪些仍未验证。成熟知识可迁往技术知识库；需要设计验收的任务或通用 EDA 工具另建对应项目，不在本仓库复制其框架。

## 每周维护

查重 → 阅读候选 → 将少量高价值候选加入索引 → 选一个当前学习项目 → 更新下一步。不要求将每周所有搜索结果全部入库。默认以 Draft PR 供用户 review。
